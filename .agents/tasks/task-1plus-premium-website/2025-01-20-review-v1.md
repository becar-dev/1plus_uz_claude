# 1PLUS Premium Brand Website — Full Greenfield Implementation

A monorepo containing a Next.js 14 frontend and Express.js backend, built from scratch as the digital presence for a creative studio in Tashkent. The frontend delivers a heavily animated homepage with Three.js hero, GSAP animations, Framer Motion transitions, and a portfolio grid backed by an Express/Prisma/SQLite API with JWT admin authentication. The approach is maximalist in animation and minimalist in infrastructure — SQLite for persistence, single-user auth, no rate limiting, no CSRF protection.

Watch for: hardcoded JWT fallback secret that ships to production (confirmed), SVG upload allowed on backend enabling stored XSS (confirmed), no token expiry validation on the client (confirmed), contact form submits to a nonexistent endpoint and silently succeeds (confirmed), admin routes have client-side-only auth guards with no middleware protection (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The JWT authentication system uses a hardcoded fallback secret (`'default-secret'`) in both the auth route and middleware, meaning if the `JWT_SECRET` env var is unset in production, every token is signed with a known value. The client stores tokens in localStorage with no expiry check — a token remains "valid" in the frontend indefinitely regardless of server-side expiry. The admin panel is protected only by a client-side redirect hook; there is no server-side rendering guard or Next.js middleware preventing unauthenticated access to admin page bundles.

The file upload endpoint accepts `image/svg+xml`, which can contain embedded JavaScript. Uploaded files are served statically via Express with no Content-Security-Policy or Content-Disposition headers, making stored XSS trivial: upload a malicious SVG, share its URL, and the browser executes the script in the site's origin context.

The Three.js hero canvas never pauses rendering when the tab is hidden or the hero scrolls off-screen, burning GPU cycles indefinitely on a 600-particle animation loop that nobody is looking at.

The contact form on the homepage submits to `/api/contact` which doesn't exist on the backend. The `handleSubmit` doesn't check the response status and shows "Message Sent!" to the user regardless, creating a false-positive UX.

The project detail page (`/work/[slug]`) is a `'use client'` component that fetches all published projects on mount just to find one by slug, then falls back to hardcoded demo data if the API is unreachable. No server-side rendering, no SEO metadata, and wasted bandwidth.

<details>
<summary>Issues (9)</summary>

1. **Hardcoded JWT fallback secret** — The `'default-secret'` string in `auth.ts` and `middleware/auth.ts` means any deployment without `JWT_SECRET` set uses a publicly known signing key. Remove the fallback and throw at startup if the env var is missing.
2. **SVG upload enables stored XSS** — The upload endpoint accepts `image/svg+xml`. Remove SVG from `allowedMimeTypes` or serve all uploads with `Content-Disposition: attachment` and a restrictive CSP.
3. **No token expiry check on client** — `getToken()` reads localStorage unconditionally. Decode the JWT and compare `exp` to current time before considering the user authenticated, or store the expiry separately and check it.
4. **Admin routes lack server-side protection** — Client-side `useRequireAuth` redirect is trivially bypassed. Add Next.js middleware (`middleware.ts`) that checks the token cookie/header for `/admin` paths.
5. **Contact form submits to nonexistent endpoint** — `/api/contact` doesn't exist on the backend. The form shows success on 404 because `fetch` doesn't throw on HTTP errors. Either implement the endpoint or check `response.ok` before showing confirmation.
6. **Canvas never pauses off-screen** — The Three.js animation loop runs indefinitely. Use `IntersectionObserver` or `document.visibilitychange` to pause `requestAnimationFrame` when the hero is not visible.
7. **Project detail page fetches all projects for one slug** — The `/work/[slug]` page loads the entire published project list client-side. Use the existing `GET /api/projects/:id` endpoint with the slug (the backend already supports lookup by slug via `findFirst`).
8. **No rate limiting on auth endpoint** — The login route has no throttling; credentials can be brute-forced. Add express-rate-limit or equivalent.
9. **Custom cursor hides system cursor globally** — The `cursor: none !important` rule on `*` breaks accessibility for users who use assistive technology that reports as `pointer: fine`. Scope the rule to the site shell only.

## JWT secret and token lifecycle

The auth route at `packages/backend/src/routes/auth.ts:34` reads:

```typescript
const secret = process.env.JWT_SECRET || 'default-secret';
```

The same pattern repeats in `middleware/auth.ts:16`. If the environment variable is unset — which is the default state of any fresh deployment that hasn't followed the `.env.example` — all tokens are signed and verified with the literal string `'default-secret'`. An attacker can forge admin tokens offline.

On the client side, `getToken()` in `lib/auth.ts` returns whatever string is in localStorage with no expiry validation. The JWT's `exp` claim is 24 hours, but the frontend will present the token to the API indefinitely. When the API finally rejects the expired token, the user sees an opaque network error rather than being redirected to login.

The seed script commits default credentials (`admin@1plus.uz` / `admin123456`) in the backend `.env` file that's checked into the repo. The `.gitignore` only covers the root-level `.env`, not `packages/backend/.env`.

## SVG upload and static file serving

```typescript
const allowedMimeTypes = [
  'image/jpeg',
  'image/png',
  'image/webp',
  'image/gif',
  'image/svg+xml',  // stored XSS vector
];
```

Uploaded files are served at `/uploads/:filename` via `express.static()` with no additional headers. SVG files are rendered inline by browsers with full script execution. The Express backend has no `X-Content-Type-Options`, `Content-Disposition`, or CSP headers on its static routes — the security headers in `next.config.mjs` only apply to the Next.js process.

## Admin panel client-side-only auth

The admin layout (`app/admin/layout.tsx`) is a plain wrapper with no auth check. Protection relies entirely on `useRequireAuth()` — a hook that reads localStorage and redirects. Consequences:

- Admin page JavaScript bundles are served to unauthenticated users (source code exposure).
- Disabling JavaScript or intercepting the redirect reveals the admin UI shell.
- If the API is unreachable, the admin interface renders in a broken state rather than denying access.

A Next.js `middleware.ts` checking for a valid token on `/admin` routes would provide server-side gating.

## Contact form dead-end

```typescript
await fetch('/api/contact', { method: 'POST', ... });
setIsSubmitted(true);  // runs even on 404
```

There's no `/api/contact` route on the backend. `setIsSubmitted(true)` executes after `await fetch(...)` completes — and `fetch` doesn't throw on HTTP error statuses, only on network failures. The user sees "Message Sent!" on every submission even though nothing was delivered.

## Three.js canvas never pauses

`requestAnimationFrame` is called unconditionally from mount to unmount. On a single-page homepage where the hero occupies the first viewport, scrolling down means the GPU continues rendering 600 particles and an extruded logo mesh to a fully off-screen canvas. The section already has a ref (`sectionRef`) that could drive an `IntersectionObserver` to toggle a `paused` flag.

## Project detail page and SEO gap

The `/work/[slug]` page is `'use client'` with data fetching in `useEffect`:

- Search engines see an empty loading spinner.
- All published projects are fetched just to `find()` one by slug.
- If the backend is down, it renders `demoProjects` — placeholder data shown to real users in production.

The backend already supports `GET /api/projects/:slug` (via `findFirst({ where: { OR: [{ id }, { slug: id }] } })`). Converting to a server component eliminates all three problems.

## Custom cursor accessibility

```css
@media (pointer: fine) and (hover: hover) {
  * { cursor: none !important; }
}
```

Users of switch-access devices, eye-tracking software, or other assistive tech that still reports as `pointer: fine` lose their cursor indicator entirely. The `z-index: 10000` can also obscure browser-native permission dialogs or cookie consent overlays that render in the page.

## Missing Content-Security-Policy

The security headers in `next.config.mjs` omit CSP entirely. Even with `'unsafe-inline'` needed for the theme init script, a CSP restricting `connect-src`, `img-src`, and `frame-src` to known origins would limit the blast radius of an XSS compromise.
